01 / THE IDEA

What problem does it solve?

Linear Regression estimates a numeric outcome from one or more input variables. It is useful when the question is not “which category?” but “how much?”—for example, how study time relates to exam marks, how floor area relates to house price, or how advertising spend relates to sales. The model fits a line or plane that summarises the average relationship in the observed data; it does not prove that one variable causes another.

A scatter plot may show a broad trend, but visual inspection alone cannot provide a consistent estimate or quantify typical prediction error. Linear regression defines a simple, interpretable rule and lets us compare predictions with observed values.

ŷ = β₀ + β₁x (one predictor); ŷ = β₀ + β₁x₁ + … + βₚxₚ (multiple predictors)

02 / METHOD

How it works, step by step

  1. 01
    Choose a numeric target and candidate predictors.
  2. 02
    Inspect units, missing values, outliers, and the shape of each relationship.
  3. 03
    Fit coefficients that minimise the sum of squared residuals in ordinary least squares.
  4. 04
    Check residual patterns and evaluate predictions on data not used for fitting.
  5. 05
    Explain the estimated slope in the units of the original variables, with uncertainty and limitations.

03 / VOCABULARY

Concepts worth knowing

Target

The numeric value the model tries to estimate.

Predictor

An input feature used to explain or estimate the target.

Intercept

The model’s estimated target when numeric predictors equal zero; this may not be meaningful if zero is outside the observed range.

Slope / coefficient

Expected change in the estimated target for a one-unit increase in a predictor, holding other predictors constant in a multiple regression.

Residual

Observed value minus predicted value. Residual patterns can reveal model misspecification.

R²

The fraction of target variation explained relative to predicting the sample mean. A high R² does not by itself prove the model is valid.

04 / IN PRACTICE

A realistic use case

A small housing study might estimate sale price from floor area. The slope gives the average price difference associated with one extra square metre in the fitted sample. Location, property age, condition, and market timing can still matter, so the estimate should not be treated as a guaranteed price.

Questions to ask before trusting the result

  • Does the data represent the population or workflow where the model will be used?
  • Are important features missing, noisy, or measured after the outcome?
  • Would a wrong prediction have unequal costs for different groups?
  • Can the result be checked on data not used to build or tune the method?

07 / INTERPRETATION

How to interpret the output

A positive slope means the predicted price tends to rise as area rises in this sample. Residuals show what the fitted rule misses. Curvature or a funnel-shaped residual cloud can indicate that a straight-line model or constant-variance assumption is inadequate.

Do not confuse a pattern with proof

A plot is evidence about the rows and variables it displays. It does not by itself establish causation, guarantee performance on future data, or show that a model will remain reliable after the data distribution changes. Document assumptions and evaluate the method in the context where it will be used.

08 / TRADE-OFFS

Strengths and limitations

Where it helps

  • Simple to explain and fast to fit
  • Coefficients retain the original feature units
  • Useful baseline for numeric prediction
  • Works well when the relationship is approximately linear

Where to be careful

  • Sensitive to influential outliers
  • May miss curves and interactions unless features are added
  • Correlated predictors can make coefficients unstable
  • Association is not causation; extrapolation beyond observed data is risky

When should you use it?

Use it when the outcome is numeric and a transparent baseline is valuable. Compare it with nonlinear methods if residuals show structure, and report test-set error rather than relying only on training fit.

09 / FIELD NOTES

A practical review checklist

  • State the prediction or discovery question in plain language.
  • Document where the data came from and what each row represents.
  • Separate training, model selection, and final evaluation when fitting a model.
  • Use metrics that match the actual task and the cost of errors.
  • Compare with a simple baseline before claiming the method is useful.
  • Explain uncertainty, assumptions, and what the result cannot establish.

10 / TAKEAWAY

What to remember

Use it when the outcome is numeric and a transparent baseline is valuable. Compare it with nonlinear methods if residuals show structure, and report test-set error rather than relying only on training fit.

The best workflow is not simply to run an algorithm and show a graph. It is to define the question, prepare the data, explain the method, examine evidence, test limitations, and communicate what can reasonably be concluded.

11 / WORKED EXAMPLE

Worked example: reading a slope

Imagine the fitted slope for floor area is positive. The model estimates a higher price as area increases, while the other included predictors are held constant. The coefficient is an average relationship in the training sample, not a promise that every larger property costs more. The intercept may be mathematically required but may not describe a realistic property if zero area is outside the data range.

  • Translate the coefficient into original units before explaining it.
  • Use MAE to describe typical absolute prediction error in the target's units.
  • Check residual plots and test-set performance before relying on the model.

12 / REPRODUCIBLE WORKFLOW

Implementation blueprint

This optional Python example shows the usual workflow for the included CSV. It is source code for running locally, not code that runs inside this static article. Install the listed libraries first, keep the dataset file beside the script, and use the printed output as a starting point for interpretation—not as a substitute for checking assumptions.

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, r2_score

df = pd.read_csv("housing_teaching_data.csv")
X = df[["floor_area_m2", "bedrooms"]]
y = df["sale_price_k"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=7
)
model = LinearRegression().fit(X_train, y_train)
pred = model.predict(X_test)
print("MAE:", round(mean_absolute_error(y_test, pred), 2))
print("Test R²:", round(r2_score(y_test, pred), 3))

How to read it: the code selects the relevant columns, applies the algorithm, and prints a summary or evaluation. Results can vary with random sampling and package versions. For a real project, document the split, parameters, metrics, and any preprocessing choices.

13 / QUALITY CHECK

Common mistakes to avoid

  • Treating R² as proof that the model is accurate on new data.
  • Ignoring nonlinearity or unequal residual spread.
  • Interpreting a coefficient causally without a causal design.

Before publishing a conclusion, ask whether the data supports the statement, whether the chart matches the stated method, and whether a reader could reproduce the workflow from the included files.
